# Small Talk hero motion — DOM and data contract (v2.3, 9 Oct 2026)

Owner: Fable session. Files: `motion/st-hero-motion.js` (controller), `motion/st-hero.css` (layout the controller depends on),
`motion/lab/index.html` (reference DOM, generated by `motion/build-lab.py` from `artwork/manifest.json`).
Install target: theme 186651934933, `assets/st-hero-motion.js` + the CSS merged into `sections/st-hero.liquid`'s stylesheet,
`<script src="{{ 'st-hero-motion.js' | asset_url }}" defer>` loaded once per page (theme.liquid or the section).

## Non-negotiables the Liquid must respect
1. Static first paint renders the first campaign completely with CSS only (sprite URLs as inline `--st-nails`, `--col`).
2. No CSS `transform`/`translate`/`scale` on any ancestor of a nail element. Nails rotate only through `rotate: var(--rot)` on
   the `.st-nail` element itself, `transform-origin: 50% 92.5%` (the cuticle anchor). The controller measures the offset chain.
3. All nail elements are absolutely positioned descendants of `[data-st-hero]` (root is `position: relative`).
4. Sprites: one WebP per set, 3 cells (signature | accent | extra), cell 204×354, anchor (0.5, 0.925). Rendered with
   `background-size: 300% 100%; background-position: calc(var(--col) * 50%) 0`.
5. Preload the first set's sprite and the default tone image; everything else lazy. Controller decodes set 2 after load and set 3 on idle.

## Behaviour (what the controller does)
- Timeline per set ≈ 2.6 s: 0.7 hold → accent 1 in (0.25) → 0.45 hold → accent 2 in while accent 1 returns (0.25) → 0.45 hold →
  accent 2 returns (0.25) → 0.45 hold → next signature flies from the hand's signature slot (0.5) with scene cross-fade and
  headline/note/CTA/accents swap at commit. Three sets, then settles ("Play again").
- Flights: Web Animations API keyframes on `transform` (translate/rotate/scale about the cuticle) and `opacity`; three keyframes with an arc.
- Pause reasons: `user`, `hold`, `hidden`, `pagehide`, `offscreen`, `reduced`. Any reason pauses running animations in place.
- Hold: pointerdown on the main nail (released on window pointerup/pointercancel/blur), Space/Enter keydown→keyup, button blur.
- Manual: tap/click the hand, ArrowRight/ArrowLeft with focus on the hand, horizontal touch swipe (≥48 px, >1.5× vertical, <700 ms).
  Manual advance uses the real flight; previous is an instant commit. Manual mode stops autoplay; the pause button becomes "Play again".
- Announcements: live region only on manual change ("{name}. {headline}"); never during autoplay.
- Reduced motion: no flights, instant manual changes, pause button hidden, autoplay never starts.
- Pause control states: `playing` (autoplay running, label Pause), `paused` (user pause, aria-pressed=true, label Play),
  `replay` (settled or manual, label Play again). While the controller is still decoding set 1 (`idle`, e.g. a background tab)
  the control reads `playing`, because autoplay is about to start (v2.2).
- Tone switch: the finger image swaps after the new tone is decoded, or after 400 ms if decoding is deferred (background tab,
  throttled pane); only a real decode error leaves the current tone in place (v2.2). Finger geometry never changes with tone.
- Failed sprite decode: the current set stays, autoplay settles silently; manual next is ignored for that set.
- Resize during a flight: flight cancelled, current set re-rendered still, autoplay resumes from the hold.
- Character: decorative (alt=""), placed by anchor (x/y 0 → left/top edge, 1 → right/bottom edge, fractions → percentage + translate)
  with bleed edges nudged past the canvas; width = widthAt390 css px at 390, scaled with viewport, capped at 19rem (2× density cap).
  v2.2: the controller writes all four inset sides inline (`auto` + the anchored sides) so the stylesheet's first-paint defaults
  (left/bottom 0) can never win over a right/top anchor. On ≥990 px a right-anchored character (`data-bleed="right"`) is pinned to
  the bottom edge by CSS (`!important`, board 2) so it clears the preview hand.
  v2.3 (≥990 px): with a left-anchored, not top-anchored character (On Me, Shaadi Shift, Diet Cherry, Wild Card) the copy and
  the CTA start at calc(clamp(9rem, 15vw, 19rem) + 3%), copy width 36%, headline clamp(3.4rem, 5vw, 4.75rem), so neither sits
  on the character. Verified 1180/1280/1440.
- Composition follows the character (CSS only, keyed on `data-bleed`, <990 px): bottom-left character (On Me, Shaadi Shift) →
  accent samples rise to top 29% / 39%; mid-left character (`data-bleed="left"`: Diet Cherry, Wild Card) → samples move to the
  right of the finger (left 80% / 73%, top 33% / 49%); top-left character (Brainwave, Pinky Promise) → copy at inset-inline 36% 5%, note
  clamp(1.2rem, 5.3vw, 1.8rem), top = just under the hand's fingertips (calc from --hand-w and --hero-h); ≤359 px: top 18%,
  note 1.2rem, headline clamp(1.7rem, 9vw, 2rem); short phones (max-height 700px): top 9%, headline clamp(1.9rem, 9vw, 2.3rem).
  The headline always ends above the main nail; right character (Green Flag) → default column. Liquid must keep `data-bleed` on the character box for set 1.
  Fades out with the next-set flight and in after commit (opacity only). Next set's character is decoded before the flight; a failed
  decode hides the character for that set. Sets 2–7 are never loaded at first paint.
- Lifecycle: `shopify:section:load` upgrades, `shopify:section:unload` destroys (listeners via AbortController, observers, animations, flyers).
- Known limitation: animation-finished promises only resolve while the document is painting; in a visible tab that is always the case.
  Hidden tabs are paused by the `hidden` reason anyway. A page opened in a background tab stays `idle` (static first paint, set 1)
  until the tab becomes visible, then set 1 decodes and the finite pass starts.
